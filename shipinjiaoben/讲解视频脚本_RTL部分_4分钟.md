# RTL 部分讲解稿（4 分钟）

[0:00]

大家好，我负责本项目的 RTL 设计与验证。接下来四分钟，我讲三件事：项目背景、主要工作与设计方案，以及 RTL 测试结果与分析。

[0:20]

在物联网边缘计算、智能传感器、音频处理和工业控制等领域，异构 SoC 架构已经成为主流技术趋势：通用 CPU 承担系统控制与任务调度，专用硬件加速器负责高吞吐量的数据运算，二者通过高速总线互连，共同达成系统级能效比最优。Cortex-M0 作为超低功耗的 32 位处理器 IP，在 MCU 芯片中应用广泛；FIR 数字滤波器凭借线性相位、天然稳定的特性，在信号处理领域具有不可替代的作用。但采用软件方式实现 81 阶 FIR，实时性能较差，因此硬件加速成为必然选择。

[0:50]

不过，我们拿到官方参考工程后发现三个问题：它只有单主设备，没有总线仲裁；没有 DMA，数据搬运只能靠 CPU；官方从机复用器和 SRAM 模型在多主并发下有隐藏缺陷，路由会被其他主机的请求刷新，读在途时写会被静默丢弃。另外官方答疑明确要求，FIR 必须支持任意非对称系数，对称优化只能作为可选分支。这四点，就是我们的设计输入。

[1:15]

架构上，CPU 通过 AHB 转 AXI 桥进入 AXI 总线；自研的双主轮询仲裁器把 CPU 和 DMA 接到共享总线上；自研的从机复用器按地址选通 SRAM、FIR、DMA 配置口和 APB 外设；6 通道 DMA 作为第二个主设备搬运数据。计分模块全部自研，官方只读复用指定 CPU 和配套桥。

FIR 采用三核架构。默认是通用全并行核，82 个独立系数寄存器乘 82 个乘法器，任意非对称系数直接可用，吞吐 1 个样本每拍。系数对称时，可以切换到 41 乘加的优化分支；再往下还有单乘法器的串行核，作为资源下限保底。一句话，任意非对称系数是基本盘，对称优化是加分项。

[2:00]

RTL 里有四个关键点。第一，累加器必须声明为 signed，否则 Verilog 会把含乘法的整式按无符号求值，这是实测踩过的坑。第二，饱和判据要查满 40 位累加器的高 10 位，因为 82 项求和可能超过正负 4，只看最高两位会漏判。第三，输出反压用 stall 冻结整条流水，同时把 din_ready 拉低，保证不丢样本。第四，双核模式位在 CLR 拍锁存，切换必然全清，杜绝脏历史样本。

DMA 这边，用头尾单拍字节 burst 加中间整字 burst，实现任意字节对齐和任意长度搬运；链式传输在通道完成后自动读取下一段描述符，不需要 CPU 干预。

[2:50]

验证按三层进行：单元与模块验证、不含 CPU 的集成验证、含 CPU 的系统测试。全量回归 17 个目标全部通过，协议检查器零违规。

Q18 的直接证据在这张图。横轴是 82 个抽头的冲激响应：对称系数时首尾相同，都是 0x0004FFF6；非对称系数时，首值是 0x16C1D27C，末值是 0xA633B39A，左右明显不同。这就是任意非对称系数的可视化证明。

指标方面，核级吞吐 1.0 个样本每拍；DMA 带宽 14.44MB/s；系统总延迟 3.04 微秒；误差按相对均方根小于 0.1%，我们用逐样本 0.0977% 的点态上界验证，比要求更严。

[3:35]

分析上，我们还定位了两个真实问题：DMA burst 提速会形成循环等待死锁，官方 mux 和 SRAM 在多主并发下会出现路由刷新和写丢失。前者固化成单拍安全配置，并把根治方向写进了文档；后者用自研的队列路由 mux 和无互斥缺陷的 SRAM 模型替代。
