# RTL 部分讲解稿（4 分钟）

[0:00]

大家好，我负责本项目的 RTL 设计与验证。接下来四分钟，我讲三部分：项目背景、代码架构与创新点，以及仿真结果。

[0:15]

在物联网边缘计算、智能传感器、音频处理和工业控制等领域，异构 SoC 架构已经成为主流技术趋势：通用 CPU 承担系统控制与任务调度，专用硬件加速器负责高吞吐量的数据运算，二者通过高速总线互连，共同达成系统级能效比最优。Cortex-M0 作为超低功耗的 32 位处理器 IP，在 MCU 芯片中应用广泛；FIR 数字滤波器凭借线性相位、天然稳定的特性，在信号处理领域具有不可替代的作用。但采用软件方式实现 81 阶 FIR，实时性能较差，因此硬件加速成为必然选择。

[0:45]

围绕赛题，我们的 RTL 要完成四件事：81 阶可配置 FIR，并且支持任意非对称系数；AXI 多主互连与仲裁；6 通道 DMA；软硬协同验证。核心指标是 1 个样本每拍、任意系数可用、总线无死锁、DMA 零差错。

[1:10]

架构上，Cortex-M0 通过 AHB 转 AXI 桥进入 AXI 总线；自研的双主轮询仲裁器连接 CPU 和 DMA；自研的从机复用器按地址选通 SRAM、FIR、DMA 配置口和 APB 外设；6 通道 DMA 作为第二个主设备搬运数据。数据流是：SRAM 中的输入样本由 DMA 送入 FIR，滤波结果再由 DMA 搬回 SRAM，CPU 只负责配置系数、下发任务和读取结果。FIR 采用三核架构：默认是通用全并行核，82 个独立系数寄存器乘 82 个乘法器；系数对称时可以切换到 41 乘加的优化分支；再往下还有单乘法器的串行核，作为资源下限保底。

[2:00]

代码上有几个关键设计。累加器必须声明为 signed，否则 Verilog 会把含乘法的整式按无符号求值；饱和判据要查满 40 位累加器的高 10 位，因为 82 项求和可能超过正负 4；输出反压用 stall 冻结整条流水，同时把 din_ready 拉低，保证不丢样本；双核模式位在 CLR 拍锁存，切换必然全清，杜绝脏历史样本。DMA 用头尾单拍字节 burst 加中间整字 burst，实现任意字节对齐和任意长度搬运；链式传输在通道完成后自动读取下一段描述符，不需要 CPU 干预。

[2:45]

创新点集中在三处。第一，把任意非对称系数做成默认路径，对称 41 乘加作为可选加速分支，兼顾合规和资源优化。第二，DMA 链式传输，多段任务自动串联，不需要 CPU 干预。第三，面向多主并发的互连设计，单事务在途仲裁加队列式响应路由，保证高并发下响应始终回到正确的主设备。

[3:10]

仿真结果方面，验证分三层：单元与模块验证、不含 CPU 的集成验证、含 CPU 的系统测试。全量回归 17 个目标全部通过，协议检查器零违规。Q18 的直接证据在这张图：横轴是 82 个抽头的冲激响应，对称系数时首尾相同，都是 0x0004FFF6；非对称系数时，首值是 0x16C1D27C，末值是 0xA633B39A，左右明显不同。指标方面，核级吞吐 1.0 个样本每拍，DMA 带宽 14.44MB/s，系统总延迟 3.04 微秒，误差按相对均方根小于 0.1%，我们用逐样本 0.0977% 的点态上界验证，比要求更严。
