## 1 系统工作原理分析

### 1.1 异构SoC与边缘计算背景

物联网边缘计算、智能传感器与工业控制场景中，通用CPU擅长系统控制与任务调度，
但做高吞吐、规则化的数字信号处理（如FIR滤波）时效率低；专用硬件加速器做这类
运算吞吐高、功耗低，但缺乏灵活性。异构SoC架构（CPU+硬件加速器+高效互连）
是业界主流形态，也是本赛题的命题背景：**在Cortex-M0 CPU上集成81阶FIR滤波
加速器与6通道DMA，通过AXI共享总线互连，由CPU固件调度软硬协同工作**。

### 1.2 FIR数字滤波原理与定点化

**原理**：N阶FIR滤波的差分方程 y[n] = Σ(k=0..N-1) h[k]·x[n-k]，其中h[k]为
滤波器系数、x为输入序列。本设计阶数81（81个系数，对应82抽头寄存器链，
任务5黄金模型按82抽头实现——含当前样本与81个延迟样本）。

**系数设计**：窗函数法低通。截止频率fc=0.15（归一化），Hamming窗，
`tools/gen_fir_golden.py` 生成，归一化使直流增益≈0.5（留6dB饱和余量）。

**定点格式**（全链路统一，误差有数可依）：
- 输入/系数：16bit Q1.15（取值范围[-1, 1-2^-15]）
- 累加器：40bit Q10.30——82项Q2.30乘积之和（每项=Q1.15×Q1.15=Q2.30）
- 输出：32bit Q1.31（饱和+舍入到Q1.31）
- 饱和判据：`acc[39:30] != acc[30]的符号扩展`即溢出，钳位到最大/最小值
  （此判据修正了计划初稿只查acc[39:38]的漏判——82项求和可超±4，见台账任务6）

**对称系数优化**（决赛创新点）：低通FIR系数对称 h[k]=h[N-1-k]，
y[n]=Σ h[k]·(x[n-k]+x[n-(N-1-k)])——81阶的82项乘加收敛为**41次乘加**：
41个17bit预加法器 + 41个乘法器 + 加法树，吞吐≥1样本/拍（任务8）。

### 1.3 AXI4协议要点

- **5通道**：写地址AW/写数据W/写响应B/读地址AR/读数据R，各自VALID/READY握手
- **burst类型**：FIXED（地址不变，外设FIFO类）与INCR（地址递增，存储类）
- **4KB边界**：单次burst不得跨越4KB边界（协议硬性规定），发起端必须拆分
- **本设计的总线风格**：CMSDK从机风格——AW/AR广播给全部从机、从机按SEL选通
  消费、mux只路由握手与响应；**无WSTRB**，字节/半字写以AWSIZE+地址低位表达
  （官方工程的风格约定，所有自研模块遵循）

### 1.4 DMA与链式传输原理

DMA（直接存储器访问）在CPU配置完描述符（源/目的/长度/控制字）后自主完成
数据搬运，CPU可并行做其它工作。本设计要点：
- **字节精度搬移**：源/目的地址任意字节对齐、长度任意字节数，零差错
  （AXI无3字节大小且本总线无WSTRB，头尾部分字节用单拍字节burst实现）
- **固定地址模式**：FIXED_SRC/FIXED_DST支持存储器↔外设FIFO类传输
- **链式传输**（决赛创新点）：每个通道完成一段传输后自动从NEXT指针读下一段
  描述符并继续执行，多段串联无需CPU干预

## 2 系统体系结构设计

### 2.1 总体架构

```
                         Cortex-M0 (官方, AHB-Lite主)
                                 │
                      ahb2axi4桥 (官方, 内建于集成层)
                                 │ m0口
              ┌──────────────────▼───────────────────┐
              │         ic_axi_master_arb            │ ← 自研多主仲裁
              │        (CPU+DMA双主轮询仲裁)          │
              └───────▲──────────────────▲───────────┘
                      │ m1口              │ 共享AXI主口
              ┌───────┴──────┐           │
              │   dma_top    │           │
              │ (6通道+1主口) │           │
              └──────────────┘           │
                              ┌──────────▼───────────┐
                              │   ic_axi_slave_mux   │ ← 自研从机复用器(队列路由)
                              └─┬──┬──┬──┬──┬──┬──┬──┘
        ┌─────────┬─────────────┘  │  │  │  │  │  └─────────┐
        ▼         ▼                ▼  ▼  ▼  ▼  ▼            ▼
   flash/axi_rom  axi_sram_sim  APB桥(UART/Timer)  GPIO0/1  fir_top   dma_top配置口  默认从机
   (0x0)         (0x20000000)   (0x40000000)      (0x4001..)(0x4002..)(0x4003..)    (DECERR)
```

数据流（软硬协同主路径）：CPU配置FIR系数 → CPU配置DMA ch0（SRAM→FIR DIN）
与ch1（FIR DOUT→SRAM）并启动 → FIR硬件逐样本滤波（1样本/拍）→ ch1回收结果
→ CPU与软件参考比对。全部指令与数据经同一AXI总线（指令Flash/ROM 0x0，
数据SRAM 0x2000_0000）。

### 2.2 结构选择与技术选型

| 决策 | 选择 | 理由 |
|---|---|---|
| CPU | 官方Cortex-M0 DesignStart集成层 | 赛题指定；AHB2AXI4桥内建（FR-6桥要求） |
| 多主仲裁 | 自研ic_axi_master_arb | 官方无（源码注释"No DMA controller - no need..."）；单事务在途+授权保持到事务完成，从协议层面杜绝死锁 |
| 从机复用器 | 自研ic_axi_slave_mux | 官方mux的B/R路由按VALID电平锁存，多主并发下路由被其它主机的请求刷新，DMA收到错误从机的R/R_LAST（实测传输夭折，见3.1/台账T13） |
| SRAM | 自研axi_sram_sim | 官方cmsdk_axi_ram_beh写地址锁存带读写互斥，"读在途+写AW重叠"时静默丢写且B仍回OKAY；仲裁器引入的1拍授权延迟恰好命中该窗口（实测栈帧写丢失致HardFault，见台账T12） |

| 地址译码 | 自研ic_axi_addr_decode | 官方译码无FIR/DMA区域 |
| 验证语言 | Verilog-2001可综合子集 | iverilog与PDS兼容 |
| 黄金模型 | Python双精度+量化口径 | 误差归因清晰（见4.2） |

### 2.4 地址映射

| 区域 | 地址范围 | 从机 |
|---|---|---|
| Flash/ROM（固件，只读） | 0x0000_0000-0x0000_FFFF | 仿真cmsdk_axi_flash / FPGA axi_rom |
| SRAM（64K） | 0x2000_0000-0x2000_FFFF | axi_sram_sim |
| APB子系统 | 0x4000_0000-0x4000_FFFF | 官方axi2apb（UART0-2/Timer/WDT） |
| GPIO0/1 | 0x4001_0000/0x4001_1000 | 官方cmsdk_axi_gpio |
| FIR | 0x4002_0000-0x4002_0FFF | fir_top |
| DMA配置 | 0x4003_0000-0x4003_0FFF | dma_top配置口 |
| 其余 | — | 默认从机（DECERR） |

FIR寄存器（0x4002_0000基址）：CTRL 0x000（bit0=CLR）、STATUS 0x004
（bit3=DOUT满/bit2=DOUT空/bit1=DIN满/bit0=DIN空）、DIN 0x008、DOUT 0x00C、
COEF[i] 0x010+4i（i=0..81）。DMA通道寄存器：通道i基址0x4003_0000+0x20i，
SRC 0x00/DST 0x04/LEN 0x08/CTRL 0x0C（bit0=GO bit1=IRQ_EN bit2=FIXED_SRC
bit3=FIXED_DST bit4=CHAIN bit[7:5]=BURST bit[10:8]=FSIZE）。

### 2.5 接口描述

（各模块端口全集见源码头注释；要点：）
- **总线约定**：AW/AR广播+SEL选通；无WSTRB；字节/半字写=AWSIZE+低位地址
- **仲裁器**：m0/m1各一组完整AXI主口，共享主口输出；授权保持到事务完成
- **DMA配置口**：CMSDK从机风格，通道i基址0x20i，中断irq_o（IRQ15接CPU）
- **固件**：裸机C，-mcpu=cortex-m0 -mthumb；SRAM/Flash直接$readmemh启动

## 3 详细设计与实现

### 3.1 多主AXI仲裁器 ic_axi_master_arb

- 写/读通道**独立授权**（互不阻塞）；授权保持到事务完成（B握手/R_LAST握手）
- 轮询指针：双方同时请求时按上次授权取反，公平无饿死
- **无死锁论证**：每个grant的master在B/R_LAST握手后即释放；从机侧由
  mux+默认从机保证响应必达；W数据仅在授权期间透传，未授权主机的挂起
  WVALID不影响总线
- 调试观测：m0_done_cnt/m1_done_cnt（完成计数）与grant_imbalance（公平性），
  压力TB断言imbalance≤2（32写+32读双主并发，协议检查器零违规）

### 3.2 FIR滤波器

**串行核 fir_core**（基线版）：82抽头移位寄存器链+1个MAC时间复用，
每样本82拍。定点处理（见1.2）：40bit累加、饱和钳位、输出取`{acc[30:0],1'b0}`
（=acc×2的低32位，Q1.31）。输出停等（`!dout_valid||dout_ready`）无损反压。
黄金对比1024样本误差<0.1%。

**对称并行核 fir_core_sym**（决赛性能/创新版）：
- 41个预加器（x[k]+x[81-k]，17bit）+41个乘法器（17×16）+6级加法树
- 输出反压：`stall=dout_valid&&!dout_ready`冻结整条流水+`din_ready=!stall`；
  释放沿同值带valid重放一拍（FIFO满条件挡住重放不入队）
- 吞吐1样本/拍（TB断言连续输出间隔恒1拍，1024样本黄金回归全对）

**从机封装 fir_top**：CMSDK从机风格；16深DIN/DOUT FIFO；DIN满时W_READY
停等（否则写被静默丢弃）；DOUT空时R_VALID=0等数据（否则返回旧值/采X）；
AW/AR按SEL门控（共享总线广播，不门控会接手其它从机的事务——实测幻影事务）；
FIFO推/弹互斥更新计数（同拍推+弹计数不变，实测竞态会流跳拍）。

**关键实现教训**（写进报告佐证"详细设计"深度）：
- Verilog-2001无符号表达式含乘法时整式按无符号求值——累加器必须声明
  `reg signed [39:0]`
- FIFO计数位宽必须能表示"满"值（16深FIFO计数需5位）

### 3.3 DMA控制器

**通道引擎 dma_channel**：读burst→16字FIFO→写burst流水；字节精度
（头尾部分写=单拍字节burst；`avail`有符号运算防hpos>0回绕）；4KB边界拆分；
FIXED_SRC/FIXED_DST固定地址模式；链式描述符（S_CH_AR读5字{SRC,DST,LEN,
CTRL,NEXT}→S_IDLE消费chain_cont续传）。读/写切换握手（FIFO满转写、空转读，
>64字节传输不死锁）；wlast组合逻辑（寄存版滞后一拍被协议检查器抓出）。

**控制器 dma_top**：6通道轮询仲裁共享1个AXI主口（授权保持到通道释放req，
即事务边界）；AXI从机配置口（通道i基址0x20i）；中断聚合irq_o；
配置读单拍R_LAST=1（AXI末拍要求）。

**零差错验证**：7类用例（对齐/非对齐/奇长/固定地址/跨4KB/错误响应/字节级
比对），6通道并发独立工作，链式3段自动串联。

**系统级死锁发现与规避**（工程难点，答辩素材）：T14尝试把固件DMA BURST
从0（单拍）提到7（8拍burst）提速，系统级仿真**死锁**。机制：ch1（DOUT读）
8拍FIXED读会追上核产出率（1样本/拍）→DOUT空→R_VALID停等；ch0（DIN写）
8拍FIXED写会填满DIN（核因DOUT满冻结）→W_READY停等；停等期间通道持有
dma_top授权（req保持至事务完成）且总线单事务在途→另一通道饿死→核无输入/
输出无人消费→循环等待。全单拍配置因"输入受限锁步"（ch0送样与ch1取样节奏
锁相）恰好安全。**规避**：固件BURST=0（安全）；**根治方向**：DMA双主口
（ch0/ch1分占ic_axi_master_arb两主口，仲裁器本就是双主设计），留作后续
优化任务（分析记录于docs/指标记录.md）。

### 3.4 从机复用器 ic_axi_slave_mux

官方mux的B/R路由选择寄存器按**VALID电平**锁存（非握手）——官方单主系统
读事务串行此简化安全；本项目多主仲裁下CPU连续取指ARVALID会在DMA读的R响应
期间刷新路由寄存器（锁存成其它从机的译码）→DMA收到错误从机的R/R_LAST→
err置位→传输夭折（实测：arsel_mux_reg被刷成flash译码，ch0看到R_LAST=0
误判协议错误）。进一步：即使握手沿锁存也不够（AR可超前于在途R，路由跟随
"最后握手的AR"会覆盖前笔事务）。**本实现**：AR/AW握手沿将译码入队、R_LAST/
B握手沿出队并推进路由（读/写各一深度4队列）；指针3位防2位回绕误判空；
出队加队列非空保护（防flash恒流幻影拍掏空队列）；W_READY组合自当前译码
（W拍时主设备保持AWADDR，仲裁器单事务在途保证归属正确）。

### 3.5 固件设计（sw/firmware/fir_demo）

流程：UART2横幅 → UART0回显64字符（3.125M波特）→ 6通道DMA自检（冻结图案
源，含中断演示，IRQ15=DMA_Handler）→ FIR软硬协同（CPU配81系数→GO ch0
（SRAM→DIN，FIXED_DST，FSIZE=2整字/拍）→轮询FIR_STATUS等首样本入FIFO再
GO ch1（防DOUT空读挂起经仲裁器R通道串行化挡死ch0，实测死锁）→dma_wait
（轮询handler累积的g_dma_irqs，不直接轮INT_STATUS——handler清位会竞争））
→ 打印out=地址。误差校验在TB侧（M0软浮点跑82×1024次乘加仿真不可接受，
且固件侧长循环校验实测触发CPU停发取指，无LOCKUP/HALT/SLEEP，根因未明）。

## 4 系统验证与分析

### 4.1 验证策略

- **TDD循环**：每任务先写自检TB（断言+PASS/FAIL）→红灯（模块未找到）→
  实现→绿灯→提交。TB用$fatal报告失败、PASS打印+$finish通过，make目标
  失败即非零退出
- **三个层级验证**（对应赛题"三个层级验证"要求）：
  1. **单元/模块验证**：tb_vip_smoke/tb_decode/tb_fir_core/tb_fir_top/
     tb_fir_core_sym/tb_dma_channel/tb_axi_rom——各模块独立TB直测
  2. **集成验证（不含CPU核，编写Testbench进行验证）**：tb_arb（仲裁器+存储）、
     tb_dma_top/tb_dma_chain（DMA+仲裁+存储+链式）、**tb_integ（VIP替代CPU，
     真实互连拓扑：仲裁器+从机复用器+地址译码+SRAM+FIR+DMA——SRAM往返+
     82系数配置+1024样本滤波黄金比对<0.1%+协议零违规）**
  3. **系统测试（含CPU核，编写C驱动代码进行测试）**：tb_soc_smoke/
     tb_soc_smoke_rom/tb_soc——CPU固件启动、UART回显、DMA自检、软硬协同
- **协议检查器**：axi_checker挂在主口，检查信号等待期稳定/4KB边界/
  W_LAST与R_LAST时序/burst类型，违规sticky+$display
- **VIP**：axi_master_vip task级读写（axi_wr/axi_rd），从机直测与仲裁测试共用；
  tb_integ中VIP作为主设备替代CPU完成全部配置与比对

### 4.2 黄金模型方法（误差<0.1%口径）

误差<0.1%的验证方法：**系数与输入先量化到Q1.15（与硬件一致）→双精度算
FIR→结果再量化到Q1.31**。这样硬件与黄金模型的差=纯实现误差（累加/舍入/
饱和），不混入输入/系数量化误差。判定阈值取0.0977%（|hw-ref|>|ref|/1024
判超标），严于赛题0.1%。激励覆盖冲激/低频正弦/高频正弦+噪声/满幅随机四段
共1024样本。
